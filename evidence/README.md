# Project Evidence – Hospital Appointment Booking System

## Overview

Supporting evidence for the course project, Hospital Appointment Booking System is located in this folder.

The project is implemented using Agile methodology with Scrum framework. The Product Backlog is managed on Trello, sprint 1 is managed on Trello, assignments, priorities, story points, deadlines and work status is managed on Trello. Version control, branching, committing, pull requests, reviews and merging done using GitHub.

The evidence in this folder provides an illustration of the use of Agile Scrum practices throughout the project by a team of three.

## Agile Methodology

The project is developed based on Agile software project management, namely Scrum software project management framework.

Scrum was chosen as it enables the project to be broken down into smaller tasks, user stories can be planned, assigned, reviewed, and completed in increments throughout the project.

The project uses the following Scrum concepts:

- Product Backlog
- User Stories
- Story Points
- Priorities
- Sprint Planning
- Sprint 1
- Task Assignment
- To Do
- In Progress
- Review
- Done
- Sprint Review
- Team Collaboration

## Product Backlog

The Product Backlog is a collection of the key requirements of the Hospital Appointment Booking System as user stories.

There were a total of 10 user stories.

Examples include:

- Patient Registration
- User Login
- Search and Filter Doctor
See the schedule of available appointment times.
- Book Appointment
- View Appointments
- Cancel Appointment
- Reschedule Appointment
- Doctor Appointment Schedule
- Administrator Management

For each backlog item the following is done:

- User Story ID
- Priority
- Story Points
- Status
- Relevant team responsibility

The Product Backlog is kept and prioritized prior to choosing items for Sprint 1.

## Trello Workflow

The Trello board illustrates the team's Scrum process.

The board is structured as such:

Product Backlog  
↓  
Sprint 1 – To Do  
↓  
In Progress  
↓  
Review  
↓  
Done

As the project progresses the cards are transferred from one of these lists to the other.

This not only displays the team's Agile workflow but also displays the visible evidence of the team's Agile workflow instead of just completed items in the backlog.
