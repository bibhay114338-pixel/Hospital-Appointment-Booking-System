# Project Scope

## Project Title

Hospital Appointment Booking System

## Project Background

Appointments are typically managed in hospitals and clinics by phone call, or by reception and/or a paper-based system. These can lead to problems like scheduling conflicts, long wait times, double bookings, missed appointments and record keeping issues.

The proposed system would be a Hospital Appointment Booking System that would be more organized to book appointments from patients to doctors. Patients can find doctors, display available appointment times, set appointments, cancel or reschedule appointments, and get appointment information.

The doctors can view the doctor's appointment schedule and the hospital administrator can manage doctor information, availability, and doctor's appointments.

This project is an academic simulation for a software development project. It is not about coding software, but instead it touches on requirement analysis, software project management principles, UML design, software testing, Trello project management and GitHub version control.

## Project Goal

The primary purpose of Hospital Appointment Booking System is to create an effective and systematic technique to organize appointments at the hospital.

## Project Objectives

The objectives of the project are to:
1. Give patients the opportunity to sign up and securely access the appointment system.
2. Allow patients to search for doctors according to specialization.
3. Let patients know what days and time slots are available for appointments.
4. Give a patient the option to reserve an appointment with a specific doctor.
5. Avoid double booking appointments.
6. Give patients the option to cancel on-going appointments.
7. Reschedule the patient's appointment to the next available appointment time.
8. Give patients an opportunity to see appointment info and booking status.
10. Make doctors' schedules available to them.
10. Give doctors administration rights so they can be able to control physician details and availability.
11. Give administrators access to and control over the appointment records.
12. Keep clear records of the requirements, design and testing of the system.

## In Scope

The proposed system will include the following functions:

* Patient registration
* User login and logout
* Patient profile management
* Search for doctors
* Go by doctor's specializations
* View doctor information
Show availability of appointments
* Book appointments
* Appointment confirmation
* View booked appointments
* Cancel appointments
* Reschedule appointments
* Prevent duplicate bookings
* Doctor schedule viewing
* Doctor appointment-detail viewing
Driven by the administrator's management of doctors.
One of the roles of the administrator is to manage the availability of doctors.
* Maintain Appointment Records by Administrator.

## Out of Scope

The project does not include the following functions:

* Online medical consultation
* Medical diagnosis
* Electronic health records
* Prescription management
* Pharmacy management
* Laboratory management
* Insurance claim processing
* Online payment processing
* Emergency medical services
* Artificial intelligence-based medical diagnosis or suggestions

## Project Limitations

The project is an academic simulation that does not have a coding component. As a result, the proposed functions are analyzed, designed and tested by documenting them, creating UML diagrams, writing test cases, and conducting design walkthroughs, but not by running a complete software product.

The project also targets primarily the appointment management aspect rather than providing a full solution to the hospital management system.
