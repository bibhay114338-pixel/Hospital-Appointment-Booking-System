# Non-Functional Requirements

Non-functional requirements specify the quality attributes, constraints and expected performance of the proposed Hospital Appointment Booking System.
| ID | Category | Non-Functional Requirement | Priority |
|---|---|---|---|
| NFR-01 | Security |The system should use authentication prior to access to protected functions and appointment information. | High|
| NFR-02 | Authorization | The system should enforce user privilege based on roles to prevent unauthorized access to functions by patients, doctors and administrators | High |
| NFR-03 | Performance | Normal operations (e.g. login, search for doctors, view appointments) should return a response within around 2-3 seconds under normal operating conditions. | Medium |
| NFR-04 | Usability | It shall be easy to navigate around and have labels with meaning for users who have basic computer or smartphone knowledge to make the common appointments. | High |
| NFR-05 | Reliability |  The system should ensure that information about appointments is maintained and there are no conflicting or duplicate appointment records. | High |
| NFR-06 | Availability | The appointment service should be available whenever users require it, except during scheduled maintenance or unexpected service interruptions. | Medium |
| NFR-07 | Data Integrity |There shall be uniformity in appointment and doctor-availability information when booking, cancelling and rescheduling operations occur. | High |
| NFR-08 | Compatibility |  the proposed web based system be compatible with commonly used modern web browsers and various screen resolutions. | Medium |
| NFR-09 | Maintainability | The documentation and design elements of the system shall be structured in a logical manner that facilitates future change and maintenance.| Medium |
| NFR-10 | Scalability |The system design should be conducive to maintaining the value of the scalability without significant redesign when the number of patients, doctors, appointment records, and available schedules increases in the future. | Medium |
| NFR-11 | Privacy | Patient and appointment information shall not be viewed by anyone other than authorized users. | High |
| NFR-12 | Accessibility | Accessibility: The interface should be easy to use, with readable text, clear instructions and navigation. | Medium |


## Summary

Non-functional requirements are the expected quality and operational characteristics of the proposed system. They add to the functional requirements and offer a set of criteria that can be taken into account while designing and testing the system.
